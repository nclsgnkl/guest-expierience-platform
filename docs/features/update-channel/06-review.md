## Security review, end to end (all confirmed)

- **Outbound only, no identity, no telemetry:** the only network calls are the two `GET`s (`ManifestClient`: `User-Agent: gxp-update/1`, `Accept: application/json`, nothing else, no cookies, no proxy, no redirects) and `docker pull` on the host; compose `ports:` unchanged (8443 only). Base URL `https://` enforced in `fetchAndDecide` unless `gxp.update.allow-plain-http` (`%test` only — verified in `application.properties`).
- **Verify before parse, on both sides:** app `ManifestVerifier.verify` precedes `ManifestParser.parse` (test-pinned); updater step 3 (`verify_any`, 64-byte signature check) precedes step 4; `version`/`artifactRef`/`sha256` are taken from the verified manifest only (`parse.sh` "evil" case).
- **No secrets or values in logs/files:** every log line is a fixed string + outcome code + at most an exception class name, a version string, an image ID or a key count (`UpdateControl.record`, `UpdateScheduler`, `gxp-updater.sh log`); no URL, no manifest byte, no key material anywhere on the path; the manager DTOs carry no raw manifest/signature (`UpdateApiTest`); `UpdaterStateDto.message` is a fixed code.
- **Root treats the app's input as hostile:** `snapshot_file` (lstat, open, `stat -L /proc/self/fd/8` device:inode/type/size compared to the entry, ≤ 64 KiB, every later read from the private copy), regex on every value before any command line (`checked`/`number_field`, `RE_*` table identical on all three sides), `to_epoch` rejects shape-valid impossible instants, arrays + `--` everywhere, no `eval`, `LC_ALL=C`; the **shadow state** (root 0600) is the only guard memory (`LAST_REQUESTED_AT`, `CURRENT_VERSION`, `TRUSTED_KEYS` read from `$GXP_STATE_FILE` only); the mirror is never read back; root never opens a path inside `$EXCHANGE` for writing (`place_file` stage + `rename(2)`, device equality checked, parent must be root-owned and not group/world-writable); the test seams are refused under `INVOCATION_ID` (proven under systemd, run 2).
- **Digest-pinned pull, dump-before-apply, rollback ladder:** `pinned_ref` refuses a contradictory embedded digest; `docker pull ref@sha256:` (Docker enforces content addressing — reviewer-verified with a wrong digest → `pull-failed`, nothing swapped); `pg_dump` before any swap, `backup-failed` aborts; `.env` rewritten by temp + `mv` keeping mode and owner; **exactly one** `compose up` per successful update, the second only on rollback; ladder image → image + (`pg_restore --list` → `DROP SCHEMA public CASCADE` → restore) → `rollback-failed` with the old image left; every request attempted at most once (state `in-progress` written before any side effect).
- **Apply window and hold:** `[applyNotBefore, +applyWindowSeconds)` with `applyWindowSeconds` validated 1…86400; outside → exit 0 and the app's reconcile moves the time; hold rule on `attemptedVersion`; manual request out-ranks it only when newer than `lastRequestedAt`.
- **Survival invariant:** every server failure is an outcome code within one 15 s budget on one worker thread (`UpdateCheckTest` never-answering listener with concurrent guest and manager requests green); the updater's only network call fails to `pull-failed` with nothing applied; `/api/guest/**` and `/api/pairing/**` untouched (contract diff); the kiosk's behaviour during the one restart is verified against `guest-data.service.ts` in Design (STALE, not a 401 wipe).

Consequence not covered by A-1: 🟡 3.
- **Conventions:** BCE layout (`boundary`/`control`/`entity`), one delegating line per Boundary method, class-level `@RolesAllowed("admin")` only, `@Transactional` on the Control, `ApiErrors` for 400/409, Panache repository, Flyway V8/V9, scheduling only in `de.gxp.infrastructure.scheduler` with Quartz crons + `SKIP` + class-name-only catch, `AuditControl.record` on every manager mutation, contract-first with the generator-only client, no `pom.xml` change; `backend/CLAUDE.md`'s "non-Java pieces beside `app/`" bullet (written 2026-08-26) matches the tree.
